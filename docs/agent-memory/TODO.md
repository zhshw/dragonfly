首版目标：单实例、多 shard 下，完成工作记忆、长期记忆、检索与后台任务的业务闭环。当前已修改同级 AMS 的适配代码，进度与证据见[实施记录](implementation-progress.md)。优先级定义：P0 定位并修复兼容阻塞，P1 完成可验收的业务闭环，P2 完成运维交付。

共 20 项实施任务：P0 8 项、P1 7 项、P2 5 项。目前勾选 18 项；下面的基础工作不计入实施任务总数。未勾选项可能已有部分实现，不能据此视为完成。

P1-04/05 已按原验收范围收口：原查询快照与四级 generation CAS 保护发布、删除、去重和访问统计；持久 prepared 输出、逐记录收据、租约 fencing、重投与实际 SIGKILL 接管保证可恢复。线程抽取模型最多自动尝试三次；发布失败保留恢复输入，Docket 终态 FAILED 后须以原身份/载荷显式重投，reconciliation 不自动扫描此类失败 thread pending。generation/receipt 永久保留以阻止晚到任务复活；自动安全 GC 为后续容量优化，不增加本清单任务。

P2-03 已实现 JSON/向量批次限制、全 AMS Docket 生产者原子准入上限 64、每轮 scheduler 上限 64，以及指标和故障窗口告警；细节见[运维说明](operations.md)。

## P0：命令合同与兼容阻塞

建议顺序：建立测试基线 → schema/普通检索 → AMS 查询合同 → 数学函数及 recency → 完整队列适配。数据库函数单测可以独立开展，完整 recency 验收依赖应用查询合同修复。

- [x] **P0-01 建立可重复的兼容测试环境**（测试/部署层）。固定 AMS 与 SDK 版本、搜索和 JSON 构建选项，使用至少两个内部 shard、隔离临时实例和固定小向量。验收：记录版本与启动命令，可重复启动/清理，基础测试无需真实模型 API。
- [x] **P0-02 验证两套完整索引 schema**（测试层）。使用 V0 实际 schema 创建 JSON 工作记忆索引与 Hash 长期记忆索引，覆盖字段编码、写入、读回、过滤、更新和删除。验收：通过锁定 RedisVL/redis-py 调用并验证解码结果，不能只用手写 RESP 代替 SDK。
- [x] **P0-03 验证普通检索合同**（测试层）。覆盖 KNN、VECTOR_RANGE、关键词和混合检索，检查向量维度、距离阈值、TAG 转义、空结果与字段别名。验收：固定数据的 ID、数量、分数及作用域符合预期，每个失败有独立最小复现。
- [x] **P0-04 修复 AMS recency 查询生成**（AMS `utils/redis_query.py`、`memory_vector_db.py`）。修复查询对象转字符串、LOAD 展开、PARAMS 传递、距离 alias、搜索过滤与聚合 FILTER 的区别，以及 offset 对候选预算的影响。验收：检查实际发送命令、SDK 返回值和第二页结果；异常 fallback 不计为通过。
- [x] **P0-05 实现通用 max/pow 函数**（Dragonfly `src/server/search/filter_functions.cc`）。先明确与目标 Redis 行为一致的参数数量、类型转换、null、非有限值和定义域语义，再增加表达式单测。验收：正常值和边界值均有断言；`max(0, 1)` 为 1、`pow(2, -1)` 为 0.5；构建并运行 `filter_expr_test`，执行格式检查。
- [x] **P0-06 验证完整 recency 排序**（Dragonfly 搜索集成测试 + AMS）。组合向量距离与时间衰减，覆盖缺失时间、未来时间、相同分数、排序与分页。验收：中间值和最终排名正确，结果非 null，明确观察到数据库侧评分分支而非 fallback。
- [x] **P0-07 确定 Docket 部署适配方式**（队列/部署层）。核对全部实际使用的 Lua 脚本；评估定向 SHA 允许与显式声明键方案，记录依赖升级后的 SHA 审计流程。验收：保留原子性，在多 shard 下验证空队列、单任务、多任务批次和失败后的键状态；不以全局关闭原子性作为修复。
- [x] **P0-08 验证真实 Docket worker**（SDK 集成测试）。使用真实序列化载荷运行立即/延迟任务，检查消费、ACK、结果、进度和两层任务状态。验收：任务实际执行，runs/AMS task/结果一致，到期 parked Hash 清理，Stream/PEL 状态符合合同。

## P1：业务闭环与一致性

- [x] **P1-01 工作记忆生命周期**（AMS）。覆盖 JSON 写入/读回、会话枚举、TTL、并发更新和文档大小限制。验收：不丢并发更新，过期会话不被索引返回，写入与 TTL 的中途失败有明确处理。
- [x] **P1-02 长期记忆完整流程**（AMS）。覆盖写入、按 ID 读取、语义/关键词/混合召回、访问统计更新、去重和删除。验收：固定输入得到预期结果及副作用，客户端与数据库评分合同一致。独立实际业务序列见 tests/agent_memory/test_business_acceptance.py，FLAT/HNSW 覆盖3检索分支、全部去重路径、统计/属性保留、作用域读删及数据库原分数。
- [x] **P1-03 强制租户隔离**（AMS API/存储/任务层）。统一 namespace/user/session 的授权与键作用域，覆盖搜索、按 ID 读取、摘要和任务接口。验收：跨租户读写/删除被拒绝，后台任务和结果键不发生跨租户碰撞。全MCP工具三传输及HTTP owner/scope、旧摘要/任务fail-closed与显式归档重派已验证；65项关联26.58秒，见[历史租户迁移](tenant-migration.md)。
- [x] **P1-04 幂等与删除竞争**（AMS）。定义任务幂等 ID、generation/版本检查、删除墓碑及保留时间。验收：重复执行不产生重复记忆，删除后晚到抽取/重试任务不能复活数据。
- [x] **P1-05 队列故障恢复**（Docket 集成测试）。覆盖 retry、cancel、worker 中断、XAUTOCLAIM 和进程重启，检查队列、runs、结果、PEL 和 AMS task。验收：无永久丢任务，重复交付由幂等机制处理，状态可解释且最终收敛。
- [ ] **P1-06 抽取、摘要与遗忘**（AMS）。先用确定性模型桩测试消息提升、语义合并、防抖、摘要更新和业务遗忘，再单独验证真实模型接入。验收：检验实际记忆内容与清理副作用，删除配置时按约定清理摘要结果。
- [ ] **P1-07 端到端验收**（跨仓库集成测试）。跑通 API/MCP → 工作记忆 → 后台抽取 → 长期记忆 → 召回 → 删除。验收：P0/P1 对应场景通过，记录实际调用分支和数据状态，不能只断言 HTTP 200。

## P2：运维与上线准备

- [x] **P2-01 schema 版本与重建**（AMS/部署层）。定义 schema、embedding 维度和模型版本迁移，以及索引重建和就绪检查。验收：不兼容配置启动即报错，重建后查询结果可核对。持久合同、全覆盖重新embedding与回滚、三阶段SIGKILL恢复和旧schema显式认领已验证，见[迁移指南](embedding-migration.md)。
- [x] **P2-02 持久化与复制验收**（Dragonfly/AMS 集成测试）。分别验证选定快照恢复和主从切换路径，检查 JSON/Hash、搜索索引、TTL、任务状态、结果、延迟队列和 consumer group/PEL。验收：记录实际恢复范围与限制，恢复后能检索并继续处理任务。选定 DF 原生快照与单副本显式提升路径，证据与边界见[持久化验收](persistence.md)。
- [x] **P2-03 可观测性与容量控制**（服务/部署层）。增加 recency fallback、Lua 失败、队列积压、任务重投、索引就绪和内存容量指标。验收：故障注入能触发告警，限制超大 JSON、向量批次和无界队列增长。
- [x] **P2-04 性能评估**（基准测试）。测量向量检索、JSON 更新和 Docket 批量调度的吞吐与前台 P95/P99 延迟，重点比较 GLOBAL 脚本对多 shard 的影响。验收：固定数据规模和配置，发布测量结果后制定批次与容量上限。固定9600次前台操作及1/16/64/256批次结果见[性能评估](performance.md)；生产硬限制由P2-03单独验收。
- [x] **P2-05 发布兼容性说明**（文档/部署层）。记录支持的版本、构建选项、启动参数、验收结果和回滚方式。多实例/Redis Cluster 另立验证计划，不沿用单实例结论。交付见[发布兼容性与回滚](release-compatibility.md)：固定候选版本/二进制标识、构建启动合同、已验收与未验收范围、维护/回滚步骤和独立 Cluster 计划。该项为说明交付，不代表上线门槛完成。
